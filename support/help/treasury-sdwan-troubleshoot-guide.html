Treasury Branch Network-troubleshooting Guide

Step-by-step guidelines for identifying and reporting network connectivity issues.

Purpose and Scope

This guide helps Treasury branch staff perform basic network troubleshooting before reporting an issue to the NOC team.

Follow the troubleshooting steps in order. Record the observations and submit the required screenshots and photographs to NOC.

This document covers individual PC problems, LAN switch issues, WAN connectivity, FatPipe gateway reachability and complete branch network outages.

01. Treasury Branch Network Architecture

Each branch has two ISP modem devices connected to the FatPipe SD-WAN device.

WAN 1 · Primary BSNL MPLS 10 Mbps · FatPipe Port 2
WAN 2 · Secondary BSNL VPN over FTTH / RailTel MPLS 2 Mbps · FatPipe Port 3

03. Troubleshooting – Single PC Issue

  1. Clear browser cache

    Close and reopen the browser. Clear cached images and files. Retry the affected application or website.

  2. Check LAN cable

    Verify that the network cable is firmly connected to the PC and wall network point. Check the link indicator.

  3. Check distribution switch port

    Check the corresponding switch port and its link/activity indicator. Report any suspected port or cable fault.

  4. Check IP address conflict

    Look for IP conflict notifications or intermittent connectivity. Record the PC IP address and report to NOC.

  5. Special attention – Ubuntu/Linux PCs

    An IP conflict involving a Linux PC may affect other devices, depending on the network configuration. If multiple PCs are affected, report this immediately to NOC.

  6. Compare with another PC

    Check whether another PC connected to the same distribution switch is working. This helps identify whether the problem is PC-specific or switch-related.

Do not manually change IP addresses, gateway or DNS settings. Contact NOC for assistance.

04. Troubleshooting – Complete Network Outage

  1. Check both ISP modem devices

    Ensure both devices are powered ON. Check power and status indicators. Take photographs of both modem front panels.

  2. Check WAN 1 – Primary

    Verify the BSNL MPLS modem connection to FatPipe Port 2. Check cable seating and link indicators.

  3. Check WAN 2 – Secondary

    Verify the BSNL VPN over FTTH or RailTel MPLS modem connection to FatPipe Port 3.

  4. Check FatPipe LAN connection

    Verify the LAN connection from FatPipe to the main network switch.

  5. Check switch connectivity

    Verify main switch and distribution switch power, uplink cables and link indicators.

  6. Test FatPipe gateway

    Obtain the branch gateway IP from NOC Admin and perform a ping test.

  7. Open FatPipe login page

    Enter the gateway IP in a browser and check whether the device login page is accessible.

05. How to Find the FatPipe Gateway IP

Use the following navigation path in the NOC Admin portal:

  1. Open NOC Admin.
  2. Select Treasury SDWAN Details.
  3. Choose the relevant Treasury branch.
  4. Locate Table 3 – FatPipe Device Configuration Details.
  5. Find the FatPipe Device IP (Gateway) column.
  6. Click the displayed IP address to open the FatPipe login page, if linked.
Always use the gateway IP corresponding to the selected branch. Do not use another branch's gateway address.

06. Ping Testing – FatPipe Gateway

Windows PCs

  1. Press Windows + R.
  2. Type cmd and press Enter.
  3. Enter the command below, replacing the example with your branch IP.
ping <FatPipe-Gateway-IP>

Ubuntu / Linux PCs

ping -c 4 <FatPipe-Gateway-IP>

Understanding Ping Results

Successful ping

Reply from the gateway indicates that it is reachable from the tested PC.

Unsuccessful ping

Request timed out, Destination host unreachable or 100% packet loss indicates that the gateway did not respond to the test.

A successful ping confirms FatPipe gateway reachability only. It does not confirm that both ISP connections or all applications are functioning correctly.

07. Check the FatPipe Login Page

  1. Open Chrome, Edge or another browser.
  2. Enter the gateway IP address in the address bar.
  3. Use HTTPS where applicable.
  4. Check whether the FatPipe login page is displayed.
  5. Capture a screenshot if accessible.
https://<FatPipe-Gateway-IP>
Do not attempt configuration changes or share administrator credentials.

08. Reporting the Issue to NOC

Branches must share the following information and supporting evidence.

Required information

  • Treasury Name and Branch Code.
  • Date and approximate time of outage.
  • Nature of issue – Single PC / Multiple PCs / Complete outage.
  • Primary and secondary WAN status.
  • FatPipe gateway IP address.
  • Ping test result.
  • FatPipe login page accessibility.

Required photographs

  • Ping test screenshot.
  • Primary WAN modem photograph.
  • Secondary WAN modem photograph.
  • FatPipe login page screenshot, if accessible.
  • Switch port photograph, if applicable.

09. NOC Investigation and ISP Escalation

  1. Verify the Branch Code and reported issue.
  2. Examine FatPipe gateway ping results.
  3. Review both ISP modem status photographs.
  4. Identify possible LAN, FatPipe or WAN connectivity issues.
  5. Report suspected ISP-related faults to the corresponding ISP.
  6. Coordinate with BSNL or RailTel for investigation and restoration.
  7. Follow up until connectivity is restored.
If the FatPipe gateway is reachable but branch services are unavailable, the NOC team will investigate possible ISP, WAN, routing or upstream connectivity issues.
If the gateway is not reachable, the NOC team will also investigate the local LAN path, switch connectivity and FatPipe device reachability. A failed ping alone does not identify the exact faulty device.

10. Important Safety Precautions

Do not perform unauthorised changes to network equipment.
  1. Do not switch OFF or restart FatPipe without NOC instructions.
  2. Do not restart or reset ISP modems without authorisation.
  3. Do not interchange WAN 1 and WAN 2 cables.
  4. Do not disconnect network cables unnecessarily.
  5. Do not modify IP address, gateway or DNS settings.
  6. Do not modify switch or FatPipe configurations.
  7. Do not perform factory resets.
  8. Do not share administrator credentials or passwords.
